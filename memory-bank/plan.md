## 1. 技术选型

| 选型 | 说明 |
| --- | --- |
| Next.js（全栈） | 前后端一体；第三方 API 密钥藏服务端，浏览器扒不到 |
| TypeScript | 类型校验，减少低级 bug |
| Tailwind CSS | 手机优先布局写得快 |
| 数据库 | M1/M2 不建库（隐私要求「用完即删」，不存最省事）；M3 才需要 |
| 其他 | 不引入重型 UI 组件库 |

## 2. 架构规范

1. 前端不碰密钥：第三方调用一律走 Next.js 后端接口（Route Handler），密钥只放 `.env.local`（已 gitignore）。
2. 合身判断引擎独立成模块（`src/lib/size-engine/`）：纯函数、可测试、前后端共用。护城河，重点维护。**不输出具体尺码（S/M/L），只给「合身 / 偏紧 / 偏松」+ 放量 + 建议方向。**
3. 图片不落盘：内存处理，用完即删。
4. 提交信息中文：`feat/fix/docs: 描述`。
5. 每个阶段结束必须能运行、能演示。

## 4. 路由设计

| 路由 | 功能 | 阶段 |
| --- | --- | --- |
| `/` | 首页：上传人像图（不强制全身，半身 / 大头均可）+ 衣服图（含 ❓ 配饰提醒）+ 身体数据（身高体重必填、三围选填）+ 衣服尺寸（选填） | M1/M1.1/M1.2 |
| `/result` | 结果页：效果图；有数据 → 合身判断+放量+建议方向+长度提示（不输出具体尺码）；合身数据不足 → 左上角标注「无尺码数据，请以实物为准」 | M1/M1.1 |
| `/privacy` | 隐私说明：三围怎么用、不存、用完即删 | M1 |
| `POST /api/tryon` | 收图 → 调试穿 API → 返回效果图（密钥在此） | M2 |
| `POST /api/advice` | 收身体+衣服数据 → 返回合身判断 | M2（M1 阶段合身计算在浏览器本地跑，同一引擎模块） |

## 6. 实现步骤

### M1（约 1~1.5 天）纯前端静态原型，不接任何真 API —— ✅ 已完成

1. 初始化项目：脚手架 + 目录结构 + 首次提交
2. 首页：手机优先布局，上传两张图，表单校验（三围明显不合理直接拦下）
3. 假效果图：现成示例图当占位，带「AI 生成」水印，两条分支（有数据/无数据）都做
4. 合身判断引擎第一版：女装上装放量表规则（放量数值 M2 前给需求方确认）
5. 照片校验 M1 版：宽高比判断（全身照应竖构图）+ 用户勾选确认；M2 换视觉模型自动判断
6. 隐私说明页
7. 本地跑通 → 演示 → 提交

### M1.1（半天）按 PRD v1.1 小改 —— ✅ 已完成（2026-10-30）

1. 身高、体重改为必填：未填时输入框下方红色小字提示，禁止进入下一步；三围保持选填
2. 衣服尺寸去掉「尺码」输入项，只留衣长、胸围、肩宽、版型（紧身 / 合身 / 宽松）
3. 版型「合体」全部改为「合身」
4. 首页标语改为「下单前，先看看自己穿上的美貌」
5. 结果页不输出具体尺码：改为「合身判断 + 放量说明 + 建议方向（看大一档/小一档）+ 长度提示」；合身数据不足 → 只出图 + 左上角标注

### M1.2（半天）人像放宽 + 配饰提醒 —— ✅ 已完成（2026-10-30）

1. 人像图不再强制全身：全身 / 半身 / 大头均可；去掉竖构图校验和「全身照确认」勾选，只校验格式与基本质量（尺寸过小拦下）
2. 衣服图区标题旁新增 ❓ 配饰提醒：桌面悬停、移动端点击（点别处收起），文案「如果是帽子、眼镜、项链等配饰，则半身效果会更好哦！」
3. 明确不做多件组合、不做多张衣服图（PRD §7）

### M2（约 2~3 天）接真实试穿 API

1. 出试穿服务商调研对比（价格/认证门槛/商用条款/效果），需求方拍板
2. 后端 `POST /api/tryon`：密钥进环境变量，图片内存过一遍、不落盘
3. 等待提示（出图约 20~60 秒，做「生成中…」进度态）
4. 接口健壮性：图片上传、超时重试、失败提示、调用次数上限
5. 照片校验升级：视觉模型判断是否全身/清晰
6. 部署 Vercel

数据闭环 + 商家合作。本期不动。

## 7. 部署方案

- **M1**：本地 `npm run dev`，浏览器 + 手机模拟视图。零成本。
- **M2**：Vercel（Next.js 亲儿子，密钥放环境变量面板；需求方有代理，国内可访问）。
- **备选**：国内云服务器（阿里云等），需备案、配置域名，慢。
