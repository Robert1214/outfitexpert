## 0. 已定决策（不得更改）

| # | 决策项 | 结论 |
| --- | --- | --- |
| 1 | 技术栈 | Next.js 全栈（App Router + TypeScript + Tailwind CSS） |
| 2 | 服装品类 | 先女装 |
| 3 | 试穿服务商 | 由 Claude 调研（阿里云 OutfitAnyone-Plus / IDM-VTON 等），出对比报告后需求方拍板 |
| 4 | 演示与部署 | M1 本地跑；M2 部署 Vercel（备选：国内服务器，需备案） |

## 1. 技术选型

| 选型 | 说明 |
| --- | --- |
| Next.js（全栈） | 前后端一体；第三方 API 密钥藏服务端，浏览器扒不到 |
| TypeScript | 类型校验，减少低级 bug |
| Tailwind CSS | 手机优先布局写得快 |
| 数据库 | M1/M2 不建库（隐私要求「用完即删」，不存最省事）；M3 才需要 |
| 其他 | 不引入重型 UI 组件库 |

## 2. 架构规范

1. 前端不碰密钥：第三方调用一律走 Next.js 后端接口（Route Handler），密钥只放 `.env.local`（已 gitignore）。
2. 尺码引擎独立成模块（`src/lib/size-engine/`）：纯函数、可测试、前后端共用。护城河，重点维护。
3. 图片不落盘：内存处理，用完即删。
4. 提交信息中文：`feat/fix/docs: 描述`。
5. 每个阶段结束必须能运行、能演示。

## 4. 路由设计

| 路由 | 功能 | 阶段 |
| --- | --- | --- |
| `/` | 首页：上传两张图 + 身体数据（选填）+ 衣服尺寸（选填） | M1 |
| `/result` | 结果页：效果图；有数据 → 建议码+提示；无数据 → 左上角标注「无尺码数据，请以实物为准」 | M1 |
| `/privacy` | 隐私说明：三围怎么用、不存、用完即删 | M1 |
| `POST /api/tryon` | 收图 → 调试穿 API → 返回效果图（密钥在此） | M2 |
| `POST /api/advice` | 收身体+衣服数据 → 返回建议码 | M2（M1 阶段尺码计算在浏览器本地跑，同一引擎模块） |

## 6. 实现步骤

### M1（约 1~1.5 天）纯前端静态原型，不接任何真 API

1. 初始化项目：脚手架 + 目录结构 + 首次提交
2. 首页：手机优先布局，上传两张图，表单校验（三围明显不合理直接拦下）
3. 假效果图：现成示例图当占位，带「AI 生成」水印，两条分支（有数据/无数据）都做
4. 尺码引擎第一版：女装上装/下装两套简化规则（放量数值 M2 前给需求方确认）
5. 照片校验 M1 版：宽高比判断（全身照应竖构图）+ 用户勾选确认；M2 换视觉模型自动判断
6. 隐私说明页
7. 本地跑通 → 演示 → 提交

### M2（约 2~3 天）接真实试穿 API

1. 出试穿服务商调研对比（价格/认证门槛/商用条款/效果），需求方拍板
2. 后端 `POST /api/tryon`：密钥进环境变量，图片内存过一遍、不落盘
3. 等待提示（出图约 20~60 秒，做「生成中…」进度态）
4. 照片校验升级：视觉模型判断是否全身/清晰
5. 部署 Vercel

### M3（远期）

数据闭环 + 商家合作。本期不动。

## 7. 部署方案

- **M1**：本地 `npm run dev`，浏览器 + 手机模拟视图。零成本。
- **M2**：Vercel（Next.js 亲儿子，密钥放环境变量面板；需求方有代理，国内可访问）。
- **备选**：国内云服务器（阿里云等），需备案、配置域名，慢。
