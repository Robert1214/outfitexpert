## 1. 技术选型

| 选型 | 说明 |
| --- | --- |
| Next.js（全栈） | 前后端一体；第三方 API 密钥藏服务端，浏览器扒不到 |
| TypeScript | 类型校验，减少低级 bug |
| Tailwind CSS | 手机优先布局写得快 |
| 数据库 | M1/M2 不建库（隐私要求「用完即删」，不存最省事）；M3 才需要 |
| 其他 | 不引入重型 UI 组件库 |

## 2. 架构规范

1. 前端不碰密钥：第三方调用一律走 Next.js 后端接口（Route Handler），密钥只放 `.env.local`（已 gitignore）。
2. 合身判断引擎独立成模块（`src/lib/size-engine/`）：纯函数、可测试、前后端共用。护城河，重点维护。**不输出具体尺码（S/M/L），只给「合身 / 偏紧 / 偏松」+ 放量 + 建议方向。**
3. 图片不落盘：内存处理，用完即删。
4. 提交信息中文：`feat/fix/docs: 描述`。
5. 每个阶段结束必须能运行、能演示。

## 4. 路由设计

| 路由 | 功能 | 阶段 |
| --- | --- | --- |
| `/` | 首页：上传人像图（不强制全身，半身 / 大头均可）+ 单品图 1~4 张（4 个上传位，含灰色 ? 配饰提醒）+ 身体数据（全部选填）+ 衣服尺寸（全部选填） | M1/M1.1/M1.2/M2.2 |
| `/result` | 结果页：桌面大图；有数据 → 合身判断+放量+建议方向+长度提示（不输出具体尺码）；合身数据不足 → 左上角标注「无尺码数据，请以实物为准」；悬停/点按看原图 | M1/M1.1/M2.2 |
| `/privacy` | 隐私说明：三围怎么用、不存、用完即删 | M1 |
| `POST /api/tryon` | 收人像 + 1~4 张单品图 → 调试穿 API → 返回效果图（密钥在此；Prompt 按单品数动态编号） | M2/M2.2 |
| `POST /api/advice` | 收身体+衣服数据 → 返回合身判断 | M2（M1 阶段合身计算在浏览器本地跑，同一引擎模块） |

## 7. 部署方案

- **M1**：本地 `npm run dev`，浏览器 + 手机模拟视图。零成本。
- **M2**：Vercel（Next.js 亲儿子，密钥放环境变量面板；需求方有代理，国内可访问）。
- **Vercel 注意**：Serverless 请求体上限约 4.5MB；多张原图 base64 后很容易超限。部署前需加客户端长边压缩或改 COS 直传（与 PRD §13.2「原图输入」需要权衡）。
- **备选**：国内云服务器（阿里云等），需备案、配置域名，慢。
