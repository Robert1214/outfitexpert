# PRD：试穿助手（outfitexpert）

> **版本**：v1.0
> **状态**：待实施
> **用途**：本项目的唯一需求依据，直接交给 Claude Code 执行。
> **硬性规则**：标「已定」的决策不得更改；有歧义先提问，不要自行发挥。

---

## 1. 背景与问题

年轻人网购衣服，有两个高频痛点：

1. **买错码**——不知道自己穿 M 还是 L，收到后不合身。
2. **买错风格**——看模特图好看，穿自己身上不是那个效果。

结果：退货率高、来回折腾、对网购失去信心。

---

## 2. 目标用户与场景

**用户**：18~30 岁，爱打扮、经常网购衣服、拿不准尺码和风格的年轻人。

**使用场景**：

1. 下单前，想知道“我该买什么码”，而不是看评论区猜。
2. 想看到“自己穿这件的大致效果”，避免“模特好看、我穿土”。
3. 不想为了试个衣服填一堆资料、注册登录。

---

## 3. 产品定位与核心价值

**一句话**：帮用户在下单前决定——这件要不要买、买什么码。

**差异化（已定，别改）**：

| 别人给用户的 | 我们给用户的 |
| --- | --- |
| 一张生成的效果图 | “这件适合你，建议买 L 码，风格偏休闲” |

**护城河在“尺码判断和建议”，不在图片。**

---

## 4. 功能需求

### 4.1 核心功能：试穿图 + 尺码建议（MVP）

**功能描述**

- 用户上传：一张全身照、一张衣服图。
- 用户可填（不强制）：身高、体重、三围（胸围/腰围/臀围）；以及这件衣服的成衣尺寸（衣长、胸围、肩宽等）。
- 系统生成试穿效果图。
- 若填了身体数据 + 衣服尺寸：额外输出「建议尺码 + 合身提示」。
- 若没填：只输出效果图，并在图片**左上角标注「无尺码数据，请以实物为准」**。

**效果图的定位（已定，禁止更改）**

- 效果图只承诺：颜色、版型、气质、大致长度（长/中/短）。
- **不承诺：下摆精确位置、厘米级合身度。**
- 合身度以尺码数据为准，不以图为准。

**页面元素**

| 元素 | 说明 |
| --- | --- |
| 上传照片 | 全身照、衣服图 |
| 身体数据（选填） | 身高、体重、三围 |
| 衣服尺寸（选填） | 衣长、胸围等，由用户自己输入 |
| 试穿结果 | 效果图；有数据时叠加「建议码+提示」，无数据时左上角标注 |

**异常情况**

- 照片不是全身 / 不清晰 → 提示重拍。
- 三围数值明显不合理（如腰围 20cm）→ 拦下并提示检查。
- 衣服尺寸没填 → 仍出图，但走「标注」分支，不给尺码建议。

### 4.2 后续（本期不做，仅规划）

- **数据闭环**：记录“试穿 → 购买 → 退货/留下”的结果，反哺尺码算法。需要商家合作。

## 5. 非功能性需求

| 项 | 要求 |
| --- | --- |
| 移动端优先 | 先做手机，桌面能看即可 |
| 隐私 | 三围是敏感个人信息：明示用途、用完即删、不用于其他目的 |
| 响应速度 | 尺码建议 1 秒内出；效果图出图要有等待提示（约 20~60 秒） |
| 简单 | 不强制注册登录，打开就能用 |
| 合规 | 生成的图需加「AI 生成」标识 |

---

## 6. 技术方案（决策，不是实现细节）

### 6.1 尺码匹配与数据来源（已定）

- 尺码用**规则匹配**：用户身体数据 → 对照衣服成衣尺寸 → 输出建议码。
- 衣服成衣尺寸由**用户自己输入**，不依赖商家或平台。
- **注意：衣服胸围 ≠ 身体胸围**，需预留“放量”，不能直接等值比较。
- 用户不输入数据时，不做尺码建议，只出效果图并标注「以实物为准」。

### 6.2 图片试穿（调第三方 API）

- 调第三方试穿 API，候选（**待评估，不写死**）：
  - 阿里云 OutfitAnyone-Plus（虚拟试穿）
  - IDM-VTON（开源，Replicate 等平台可调）
  - 其他虚拟试穿服务
- **选型标准**：按张价格、是否需要企业认证、能否商用、效果是否够看。

### 6.3 整体结构

```
用户（网页）
  → 你的后端（持有 API 密钥）
  → workflow（校验 → 尺码匹配 → 试穿 → 生成建议）
  → 返回给用户
```

### 6.4 模型分工（已定，禁止更改）

**“写代码的模型”和“画图的模型”是两回事。**

- Claude Code 用的模型负责写代码，现在接的 DeepSeek 就够，**不用换**。
- 图片试穿的效果，由 workflow 里调的**试穿 API** 决定，跟 Claude Code 接什么模型无关。

---

## 7. 明确不做（MVP 阶段）

- ❌ 不承诺“效果图 = 真实上身效果”（尤其下摆位置、厘米级合身度）
- ❌ 不做支付、购物车、商品上架
- ❌ 不做登录注册、社区、分享
- ❌ 不接商家后台（第二期以后）
- ❌ 不做任何未成年人相关的内容

---

## 8. 验收标准（怎么算做成）

MVP 满足以下才算完成：

- [ ] 上传两张图，能生成效果图
- [ ] 填了数据 → 给出建议码 + 提示；没填 → 只出图并在左上角标注「无尺码数据，请以实物为准」
- [ ] 照片不是全身 / 不清晰时，能提示重拍
- [ ] 三围明显不合理时，能拦下
- [ ] 生成的图带有「AI 生成」标识
- [ ] 三围数据用完即删，页面有隐私说明
