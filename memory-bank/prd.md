# PRD：试穿助手（outfitexpert）

> **版本**：v1.5（配饰类型 + 4 图复测 + 再来一次 + 刷新缓存，见 §12）
> **状态**：M2.2 进行中（配饰类型、4 图复测、再来一次、刷新缓存已完成；Vercel 待做）
> **用途**：本项目的唯一需求依据，直接交给 Claude Code 执行。
> **硬性规则**：标「已定」的决策不得更改；有歧义先提问，不要自行发挥。

---

## 1. 背景与问题

年轻人网购衣服，有两个高频痛点：

1. **买错码**——不知道自己穿 M 还是 L，收到后不合身。
2. **买错风格**——看模特图好看，穿自己身上不是那个效果。

结果：退货率高、来回折腾、对网购失去信心。

---

## 2. 目标用户与场景

**用户**：18~30 岁，爱打扮、经常网购衣服、拿不准尺码和风格的年轻人。

**使用场景**：

1. 下单前，想知道“合不合身”，而不是看评论区猜。
2. 想看到“自己穿这件的大致效果”，避免“模特好看、我穿土”。
3. 不想为了试个衣服填一堆资料、注册登录。

---

## 3. 产品定位与核心价值

**一句话**：帮用户在下单前决定——这件要不要买、合不合身。

**差异化（已定，别改）**：

| 别人给用户的 | 我们给用户的 |
| --- | --- |
| 一张生成的效果图 | “这张图 + 合身判断 + 具体建议” |

**护城河在“合身判断和建议”，不在图片。**

## 4. 功能需求

### 4.1 核心功能：试穿图 + 合身判断（MVP）

**首页标语（已定）**

> 下单前，先看看自己穿上的美貌

**上传规则（已定）**

| 项 | 规则 |
| --- | --- |
| 人像图 | **1 张**。全身照、半身照、大头照**都可以**，不强制全身 |
| 衣服图 | **1~4 张单品图**（4 个上传位）。每个格子要选类型：**衣服 / 配饰 / 鞋**；眼镜、帽子、项链选「配饰」。类型决定 Prompt 是“替换服装”还是“佩戴配饰”（见 §6.2、§13.3）。也可以传一张整套搭配图作为 1 张 |

**配饰提醒标识（已定）**

- 位置：单品图上传区标题旁，一个 **?** 小图标（**灰色**，不用红色）。
- 桌面端：**鼠标悬停**显示气泡。
- 移动端：**点击** ? 显示气泡（手机没有悬停，禁止只做 hover）。
- 气泡文案（原样使用）：

  > 如果是帽子、眼镜、项链等配饰，则半身效果会更好哦！

**功能描述**

- 用户上传：人像图 1 张（全身 / 半身 / 大头均可）+ 单品图 1~4 张。
- 每个单品格有类型选择（衣服 / 配饰 / 鞋），默认衣服；眼镜、帽子、项链必须选「配饰」，否则可能被当成衣服而不生效。配饰参考图尽量用干净商品图，不要带模特脸/手。
- **身体数据（全部选填）**：身高、体重、胸围、腰围、臀围；不填也能进入下一步，只出效果图。
- **衣服尺寸（全部选填）**：衣长、胸围、肩宽、**版型**（紧身 / 合身 / 宽松）。
- 系统生成试穿效果图。
- 若数据足够：额外输出「合身判断 + 放量说明 + 建议方向 + 长度提示」。
- 若合身数据不足（缺身体胸围或成衣胸围）：不做合身判断，图片**左上角标注「无尺码数据，请以实物为准」**。

**合身判断的数据依赖（已定，务必按此实现）**

| 用户提供了什么 | 系统能给什么 |
| --- | --- |
| 身高 + 衣长 | 长度大致位置（如「大致到大腿中部」） |
| 身高 + 身体胸围 + 成衣胸围 + 版型 | 合身判断（合身 / 偏紧 / 偏松）+ 放量数值 + 建议方向 |
| 缺胸围 | 只给长度提示，**不做合身判断** |
| 缺衣长 | 只给合身判断，**不给长度提示** |
| 什么都没填（衣服尺寸全空） | 只出效果图，左上角标注「无尺码数据，请以实物为准」 |

**输出内容（已定，不再输出具体尺码）**

- 合身判断：合身 / 偏紧 / 偏松
- 放量说明：如「胸围放量约 4cm，对合身版型偏紧」
- 建议方向：如「建议看大一档」或「建议看小一档」
- 长度提示：如「大致盖住臀部上沿」
- 免责句：如「以上按你填写的成衣尺寸估算，最终以实物试穿为准」

> 注意：因为不再要求用户填写衣服的「尺码」标签，系统**不得**输出「建议选 L 码」这类具体尺码，只能给方向和判断。

**效果图的定位（已定，禁止更改）**

- 效果图只承诺：颜色、版型、气质、大致长度（长/中/短）。
- **不承诺：下摆精确位置、厘米级合身度。**
- 合身度以尺码数据为准，不以图为准。
- 人像为半身/大头照时，效果图可能只呈现上半身，这是正常的，不做额外承诺。

**页面布局（v1.4，桌面端）**

- 页面最大宽度约 1280px；桌面端双栏，手机端单列。
- 左栏：上为模特图（1 张），下为单品图（4 个上传位；桌面 4 列、手机 2×2）。
- 右栏：身材数据、衣服尺寸两张卡**横向并排**，两张卡的高度与左栏整体视觉对齐（底部对齐）。
- 提交按钮在双栏下方，桌面端右对齐。

**试穿结果页（v1.4）**

- 桌面端效果图为大图（左栏约 1.6 份宽），右侧放合身建议；手机端上下排列。
- **鼠标悬停效果图显示原图，移开恢复效果图；手机端点按切换。** 未悬停时显示效果图，并保留「AI 生成」标识。

**页面元素**

| 元素 | 说明 |
| --- | --- |
| 上传 · 人像图 | 1 张；全身 / 半身 / 大头均可 |
| 上传 · 单品图 | 4 个上传位，1~4 张均可；每格选衣服/配饰/鞋；可含整套搭配图 |
| 配饰提醒 | 单品图区标题旁灰色 **?**，悬停（桌面）/ 点击（手机）显示气泡 |
| 身体数据 | 身高、体重、三围；**全部选填**，不填也能出图 |
| 衣服尺寸 | 衣长、胸围、肩宽、版型（紧身/合身/宽松）；全部选填 |
| 试穿结果 | 桌面大图；有合身数据时叠加「判断+建议」，无数据时左上角标注；悬停/点按看原图 |

**异常情况**

- 照片看不清主体 / 光线过暗 → 提示重拍。
- **人像图或单品图未上传 → 拦截提示，不发起生成。**
- 三围或衣服尺寸数值明显不合理（如腰围 20cm）→ 拦下并提示检查（只校验已填字段）。
- 衣服尺寸全空 → 仍出图，但走「无尺码数据」标注分支，不做合身判断。

### 4.2 后续（本期不做，仅规划）

- **数据闭环**：记录“试穿 → 购买 → 退货/留下”的结果，反哺合身算法。需要商家合作。
- **多件组合搭配**：**已支持 1~4 张单品图同时换装**（见 §13.3）；配饰必须选「配饰」类型；超过 4 张、同一单品多色对比暂不做。

## 6. 技术方案（决策，不是实现细节）

### 6.1 合身判断与数据来源（已定）

- 判断用**规则**：用户身体数据 → 对照衣服成衣尺寸 → 输出判断（不用 AI 猜）。
- 衣服成衣尺寸由**用户自己输入**，不依赖商家或平台。
- **注意：衣服胸围 ≠ 身体胸围**，需预留“放量”，不能直接等值比较。
  - 参考放量区间（**待用真实反馈校准**）：紧身 4~6cm、合身 6~10cm、宽松 10~16cm
- 版型只有三种：**紧身 / 合身 / 宽松**。
- **不再使用「尺码」标签**（S/M/L 各品牌不一致，没有可比性），因此不输出具体码数。
- 用户不提供胸围数据时，不做合身判断，只出效果图并标注「以实物为准」。

### 6.2 图片试穿（已选定腾讯云 MPS AI 换装）

- **服务商**：腾讯云 MPS「AI 换装」（`ProcessImage` 接口），异步任务 + 轮询，已接入并验证。
- **选型理由**：国内、支付宝付款、官方中文文档与 SDK、支持半身/大头照、单价约 1 元/张。
- **当前采用配置（已实测最优组合）**：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| 模型 | `tryon-1.0-lite` | 约 1 元/张；`flash` 约 2.12 元/张，作备选 |
| 输出分辨率 | `1K` | 2K 耗时多约 20 秒、无额外细节收益，不采用 |
| 输入 | **原图上传，不做 900px 压缩** | 输入清晰度决定细节（见 §13.2） |
| 参考图 | `garment` / `accessories` / `shoes` × 1~4 + `identity` | 类型由单品格选择；identity 用于保持人脸（见 §13.4）；Prompt 按类型和数量生成 |
| Prompt | 强调「严格保持五官、脸型、肤色、发型不变」；按类型生成“替换服装 / 佩戴配饰 / 替换鞋” | 见 §13.4；配饰参考图建议干净商品图 |

- **已排除**：IDM-VTON（Replicate，仅限非商业用途）。
- **未采用**：阿里云 OutfitAnyone（入口难找）、FASHN / Genlook（需外币卡）。

### 6.3 整体结构

```
用户（网页）
  → Next.js 后端（持有密钥）
  → 上传中转（COS 签名 URL，用完即删）
  → 腾讯云 MPS AI 换装（异步任务 → 轮询）
  → 返回效果图 URL
```

### 6.4 模型分工（已定，禁止更改）

**“写代码的模型”和“画图的模型”是两回事。**

- Claude Code 用的模型负责写代码（DeepSeek），与产品出图效果无关。
- 图片试穿的效果，由腾讯云 MPS 的换装模型决定。

## 7. 明确不做（MVP 阶段）

- ❌ 不承诺“效果图 = 真实上身效果”（尤其下摆位置、厘米级合身度）
- ❌ 不输出具体尺码（S/M/L），只给合身判断和方向
- ❌ **不承诺帽子 / 眼镜类配饰下五官完全不变**（会触发头部/脸部重绘，见 §13.4）
- ❌ 单品图超过 4 张；不做同一单品的多色 / 多码对比
- ❌ 不做帽子 / 眼镜 / 项链的二级类型选择；统一选「配饰」，由 Prompt 按“佩戴”处理
- ❌ 不做支付、购物车、商品上架
- ❌ 不做登录注册、社区、分享
- ❌ 不接商家后台（第二期以后）
- ❌ 不做任何未成年人相关的内容

## 13. M2 实测结论（2026-10-30）

> 这一节记录实测数据与踩过的坑，避免以后重复试错。改动相关参数前请先读这里。

### 13.1 费用

| 模型档位 | 单价 | 状态 |
| --- | --- | --- |
| `tryon-1.0-lite` | 约 1 元/张 | **当前采用** |
| `tryon-1.0-flash` | 约 2.12 元/张 | 备选（更高质量，未采用） |

- lite 档下 1K 与 2K 同价，但 2K 更慢，故不启用。

### 13.2 分辨率：输入决定细节，输出只决定画布

| 配置 | 输出像素 | 总耗时 |
| --- | --- | --- |
| 900px 输入 + 1K 输出 | 1080 × 1446 | 41.6 秒 |
| 900px 输入 + 2K 输出 | 1440 × 1929 | 60.3 秒 |
| 原图输入 + 1K 输出 | 约 1080 宽级 | 约 60 秒 |

**关键结论：**

- 早期前端把上传图压缩到最长边 **900px**（M1 为塞进 localStorage 留下的逻辑），导致模型"看不清五官只能猜" → 已改为**原图上传**（后端不再压缩）。
- **2K 输出只是把画布放大，不产生新细节**，且多耗约 20 秒 → **不采用**。
- 若将来觉得糊，先查**输入**是否被压缩，而不是先加输出分辨率。

### 13.3 多件能力

- ✅ **支持「一张套装图」同时换上装 + 下装**：图中上下排列的整套搭配，模型会自动分割并分别替换。
- ✅ **支持 1~4 张独立单品图同时换装**：后端 `ImageSet` 传 `garment / accessories / shoes` × N + `identity`；Prompt 按类型和数量动态生成；1~4 张均已实测（4 图为 3 衣服 + 1 副眼镜，眼镜选「配饰」）。
- ✅ **单品格类型**：界面每个格子可选 衣服 / 配饰 / 鞋；眼镜、帽子、项链选「配饰」，Prompt 写“佩戴配饰”，不混在“替换服装”里。
- ⚠️ **2026-10-31 事故复盘**：4 图含眼镜、但 4 个参考图全按 `garment` 传时，MPS 返回原图；去掉眼镜的 3 图成功。根因是配饰类型与“佩戴”指令缺失；修复后 4 图（3 衣服 + 眼镜配饰）复测通过。
- ⚠️ 配饰参考图如果带模特脸/手，模型可能把脸/手一起画进结果；建议用干净商品图。4 件纯衣服组合的稳定性仍以实测为准。
- **产品结论**：用户可分开上传最多 4 件单品，也可只传一张套装图；超过 4 张不做。

### 13.4 五官变形（重要）

**现象**：换装后人物五官被"磨平 / 走形"。

**根因（两条）**：

1. 输入图被压缩到 900px —— 模型看不到细节，只能生成"想象的脸"（已修复，改善明显）。
2. **帽子、眼镜等面部配饰会触发模型重建头部/脸部**（帽子要戴在头上、眼镜要贴脸，遮挡关系都要重画），脸在同一个区域里，可能被顺手重画。

**缓解手段（已采用）**：

- `identity` 参考图（传同一张人像）。
- Prompt 明确写：「严格保持[图片1]中人物的五官、脸型、肤色、发型完全不变，不要重新生成面部」。

**结果**：加 identity + Prompt 后，效果提升到**约 85% 可用**，目标用户（真实使用者）确认「很棒」。

**这是 2D 换装的固有边界，不是缺陷，不追求 100%。**

### 13.5 已知边界（避免过度承诺）

| 边界 | 说明 |
| --- | --- |
| 多单品 | 最多 4 件；4 件组合已通过含配饰场景，4 件纯衣服等更多组合仍以实测为准，不承诺每件都完美 |
| 合身度 | 图片不反映真实合身，合身判断仍靠数据（§6.1） |
| 帽子 / 眼镜类配饰 | 会重绘头部/脸部，五官有轻微变化，不承诺完全一致 |
| 配饰参考图 | 带模特脸/手时，模型可能把脸/手一起画进结果；建议干净商品图 |
| 等待时长 | 约 60 秒，必须在界面上明确告知 |
| 成本 | 每次调用约 1 元，靠每日次数上限（10 次/人/天）控制 |
